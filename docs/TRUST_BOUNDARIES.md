# Trust Boundaries

## Status

This document identifies planned trust boundaries and required controls. It does not implement those controls.

## Boundary Matrix

| Boundary | Trusted and untrusted inputs | Authentication expectations | Authorization expectations | Data crossing boundary | Sensitive assets | Required validation | Audit requirements | Expected failure behavior |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Browser and client applications | User commands are untrusted; rendered stored data is untrusted. | Users authenticate through approved identity flow. | Server enforces every protected action. | Commands, views, traces, reviews, exports. | Tenant data, review evidence, gate decisions. | CSRF or equivalent protections where relevant, input validation, output encoding. | Log sensitive commands and denied access. | Deny action and show safe error. |
| Public API boundary | Requests, headers, bodies, files, and idempotency keys are untrusted. | Require user or service identity. | Enforce tenant and resource permissions server-side. | Dataset, run, trace, artifact, review, gate, and export data. | Tenant content and credentials references. | Schema, size, tenant, rate, and replay validation. | Audit protected mutations and denials. | Return bounded errors without leaking tenant data. |
| Authentication provider | Identity assertions are trusted only after verification. | Verify tokens, issuer, audience, expiry, and signature. | Map verified identity to tenant membership. | Identity claims and session state. | User identity and session tokens. | Token and session validation. | Audit login-sensitive events and failures where available. | Reject unknown or invalid identity. |
| Control API | Internal commands from clients and workers may be malformed. | Require authenticated caller or service identity. | Central authorization point for protected operations. | Domain commands, reads, state transitions. | Versioned artifacts, gates, audit state. | Command validation and policy checks. | Audit material actions and denials. | Fail closed and avoid partial state. |
| Background workers | Queue payloads and provider responses are untrusted. | Workers use scoped service identity. | Verify tenant and operation before processing. | Run commands, traces, artifacts, evaluator outputs. | Provider credentials, tenant artifacts. | Idempotency, schema, tenant, retry, and output validation. | Audit state transitions and failures. | Retry safely or mark terminal failure with evidence. |
| Queue or workflow system | Messages may be delayed, duplicated, tampered, or stale. | Workers authenticate to queue or workflow system. | Message content does not prove authorization. | Commands, job state, correlation IDs. | Tenant operation metadata. | Signature or integrity checks where practical, idempotency keys, tenant verification. | Audit enqueue, start, retry, cancel, and terminal state. | Discard invalid messages and preserve diagnostic evidence. |
| Database | Queries and migrations can affect tenant data. | Services authenticate with least privilege. | Application enforces tenant scope and resource policy. | Structured tenant and audit state. | All tenant records and audit events. | Tenant constraints, query scoping, schema validation. | Audit access-sensitive mutations. | Fail closed and avoid cross-tenant fallback. |
| Object storage | Uploaded bytes and paths are untrusted. | Services authenticate with scoped credentials. | Object access requires tenant and resource authorization. | Datasets, artifacts, exports, traces, reports. | Sensitive artifacts and private evaluation data. | Type, size, path, hash, malware controls where practical. | Audit upload, read-sensitive export, deletion. | Quarantine or reject invalid objects. |
| Model and embedding providers | Provider responses and telemetry are untrusted for policy decisions. | Use environment and tenant-isolated credentials. | Provider calls require authorized tenant operation. | Prompts, context, outputs, embeddings, usage. | Prompts, completions, retrieved context, credentials. | Request bounds, response validation, redaction, retention disclosure. | Audit provider calls at metadata level. | Retry or fail with disclosed provider limitation. |
| External target applications | Target traces and outputs are untrusted. | Ingestion uses service identity or signed client credentials. | Target may write only to authorized tenant resources. | Runs, traces, spans, artifacts, errors. | Target outputs and private app data. | Schema, tenant, size, idempotency, source validation. | Audit ingestion and rejection. | Reject invalid ingestion without trusting payload claims. |
| Trace ingestion sources | Trace payloads and artifact references are untrusted. | Require SDK or integration authentication. | Verify tenant and target access. | Spans, artifacts, metrics, errors. | Sensitive trace data. | Canonical schema, limits, timestamps, resource references. | Audit accepted and rejected trace batches. | Drop or quarantine invalid trace evidence. |
| Tool-execution environments | Tool inputs, outputs, and side effects are high risk. | Tool execution uses scoped service identity. | Tool use must be authorized by workflow and tenant policy. | Tool calls, arguments, outputs, files, network requests. | External systems, credentials, tenant data. | Schema, side-effect policy, egress, output sanitization. | Audit tool calls and blocked actions. | Block unsafe calls and preserve error evidence. |
| Human reviewers | Reviewer decisions and comments may be biased or sensitive. | Reviewers authenticate as users. | Review assignment and evidence access are tenant-scoped. | Evidence, comments, decisions, adjudication. | Sensitive review content and identities. | Role, assignment, rubric version, conflict checks. | Audit assignment, submission, adjudication. | Deny access or require reassignment. |
| CI systems | Status requests and callbacks may be spoofed. | Use signed tokens or verified integration identity. | Gate reads and decisions require scoped permission. | Commit metadata, gate requests, deployment status. | Gate decisions and release evidence. | Signature, replay, repository, branch, and tenant validation. | Audit gate checks and callbacks. | Fail closed for deployment gates. |
| Deployment systems | Deployment requests may be stale or unauthorized. | Verify integration identity. | Only authorized gates may affect deployment. | Gate decisions, overrides, environment metadata. | Release controls and audit records. | Environment, commit, gate version, callback verification. | Audit decision and override path. | Block deployment when evidence is invalid. |
| Administrative operators | Operator actions are powerful and high risk. | Strong authentication and separate admin role. | Least privilege and reason-scoped access. | Tenant settings, access changes, support actions. | Tenant data, audit logs, credentials references. | Role, reason, scope, approval where required. | Audit every administrative action. | Deny by default and alert on suspicious access. |
